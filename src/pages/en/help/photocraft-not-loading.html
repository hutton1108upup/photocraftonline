PhotoCraft Not Opening: Identify Which Part Failed

  • A loading message, blank area or WebGPU notice: start with graphics and network checks below.
  • The editor is visible but one PSD or image fails: go to file checks.
  • An application downloaded to your computer does not launch: go to desktop checks.

1. Browser Editor Will Not Start: Check Graphics Support

  1. Use a current desktop Chrome or Edge and open our editor. Its toolbar and canvas must appear before startup is complete.
  2. For “WebGPU is unavailable in this browser,” check Chrome Settings → System → Use graphics acceleration when available, or search Edge Settings for graphics acceleration. Restart the browser after a change.
  3. If the same notice remains, try another desktop browser with working graphics support or official desktop downloads. Do not disable browser security to work around it.

Success check: the loading message disappears and the editor toolbar and canvas appear. The surrounding website header alone does not establish editor startup.

2. Loading Stalls or Fails: Inspect Editor Downloads

  1. The first load requests about 25 MB of WebAssembly. Check that the download is progressing before repeatedly refreshing.
  2. Before opening a work document, you can choose Retry editor. If you have unsaved work, address backups first; retrying and refreshing discard unsaved changes.
  3. If startup still fails, press F12 → Network, reload and check failed .wasm or photocraft-web-…js requests. Record the HTTP status or blocking reason.
  4. If resources return successfully but startup fails, record the visible error and compare another browser. This does not show that your image is damaged.

Success check: resources finish loading and the editor UI appears. An HTTP 200 alone does not establish successful engine initialization.

3. The Editor Opens, but an Image or PSD Does Not

  1. Download our 640 × 400 practice PNG and try opening it in the editor first.
  2. If that works, try a copy of your own file. If only a large image or complex PSD fails, record the format, size and failing step. Keep the original.
  3. Follow the save and export lesson, check browser downloads, then reopen the exported PNG.

Success check: the practice image appears and its exported PNG still displays when reopened. This small exercise does not establish compatibility with every PSD layer, font or effect.

4. Desktop App Will Not Launch: Check Package and Architecture

  1. Choose your system and CPU on the download page. Source ZIPs, Web ZIPs and desktop installers serve different purposes.
  2. For Windows portable, right-click the ZIP → Extract All, then run from the complete folder. For MSI, use its installer. Match checksums to the same release and filename.
  3. If the app opens but only one document fails, return to file checks instead of repeatedly reinstalling.
  4. Keep the exact system prompt and error, and follow the current official instructions. We did not repeat desktop installation or Mac/Linux startup tests in this update.

Success check: the desktop editor opens and displays the practice PNG. Downloading or extracting successfully is not enough.

5. Still Stuck: Record a Reproducible Problem

Record your OS, browser version, hosted build ID, exact failing step, visible error and a screenshot without private content. Search upstream Issues first. Describe engine behavior separately from this website’s loading behavior, and keep private images out of public reports.
